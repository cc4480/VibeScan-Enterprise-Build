# Seclayer

Black-box web security scanning that produces a plain-English report.

Point Seclayer at a URL and it probes the live site from the outside — no
agent, no source access, no credentials — then grades what it finds A–F and
explains each issue in language a non-specialist can act on. Deep scans add a
DeepSeek-generated analysis and a paste-ready fix prompt tailored to the stack
it detected.

It was built for people shipping apps faster than they can audit them: sites
generated by AI builders, Supabase/Firebase backends wired up in an afternoon,
side projects that quietly went to production.

> **Status: early access.** Every scan and continuous monitoring are free right
> now. Stripe code is still in the tree but dormant — `POST /scans` queues the
> job immediately and never returns a checkout URL.

## What it checks

Roughly **73 distinct checks on a Basic scan and 97+ on a Deep scan**: HTTP
response headers and cookie flags, TLS (Qualys SSL Labs grade plus certificate
expiry), DNS and email authentication (SPF/DMARC/DKIM/DNSSEC), technology
fingerprinting (~60 technologies), active HTTP path probes, known-CVE version
matching, JWT analysis, subdomain takeover, vibe-stack database exposure
(Supabase RLS, open Firebase rules), source-map exposure, JavaScript secret
scanning, path traversal, and a 20-page site crawl that re-runs the header and
cookie checks on each page.

**[`SCAN_COVERAGE.md`](SCAN_COVERAGE.md) enumerates them** — each check, its
severity, and which tier runs it. (It documents the probe modules; the TLS
checks, which live in the scan worker, aren't listed there yet.)
[`SCAN_TESTS.md`](SCAN_TESTS.md) records how they were validated against real
targets.

Findings are scored `Critical +30 / High +15 / Medium +5 / Low +1` into a risk
score, which maps to a letter grade (A: 0–10, B: 11–25, C: 26–45, D: 46–65,
F: 66+).

### Signal quality is the point

A scanner that cries wolf teaches people to ignore it, so suppression rules are
treated as a first-class feature rather than an afterthought — SPA and
multi-tenant catch-all detection, structural markers instead of keyword
matches, entropy thresholds on secret patterns, session vs. non-session cookie
classification, and public-by-design keys (`pk_live_`, `sb_publishable_`,
Firebase `AIza…`) never flagged on their own. The rules every new probe is
expected to follow are written up in
[`replit.md`](replit.md#scanner-false-positive-prevention).

## ⚠️ Scan only what you are allowed to scan

Deep scans send active probes — path enumeration, traversal attempts, a
crawler. Running them against infrastructure you neither own nor have written
permission to test is likely illegal in your jurisdiction and violates most
providers' terms of service. You are responsible for your targets.

## Architecture

A pnpm-workspaces monorepo. React front end, Express API, PostgreSQL, and an
in-process job queue — a scan is a queued job, not a request you hold open.

```
artifacts/
  api-server/       Express 5 API — src/routes, src/lib (the scan engine), src/middlewares
  vibescan/         React 19 + Vite front end — src/pages, src/components
  mockup-sandbox/   Design component preview server
lib/
  api-spec/         openapi.yaml — the API contract source of truth
  api-zod/          Zod schemas generated from the spec
  api-client-react/ Generated API client
  db/               Drizzle schema + migrations
  replit-auth-web/  Auth utilities (unused — see below)
```

- **Stack**: React 19, Vite 7, Tailwind, Wouter, TanStack Query / Express 5,
  TypeScript ESM, pino, pg-boss / PostgreSQL 16 via Drizzle ORM / esbuild.
- **No login.** Identity is a UUID minted into `localStorage`
  (`vibescan_client_token`) and sent as `Authorization: Bearer`. `lib/replit-auth-web`
  is vestigial.
- **Job queue in-process.** pg-boss runs inside the API server and owns scan
  jobs plus the EOL/CVE refresh and monitor schedulers. No separate worker to deploy.
- **Everything external degrades gracefully.** DeepSeek, Resend, and Stripe each
  check for their key at startup and log a warning if absent; the app stays
  functional without any of them.
- **Bring your own AI key.** Users can save a personal DeepSeek key in Settings
  to spend their own credits instead of the server's. Keys are AES-256
  encrypted at rest with `ENCRYPTION_KEY` and never re-displayed.
- **Monitoring is risk-adaptive.** Rescan cadence follows the grade — A every 14
  days, B/C every 7, D/F every 3 — with Slack-compatible webhooks for CVE
  alerts, regressions, and certificate expiry.

## Getting started

**Prerequisites:** Node 22.9+ (24 recommended), pnpm 10, PostgreSQL 16.

```bash
pnpm install

# Shared libs use TypeScript project references — their dist/*.d.ts is what
# typecheck actually reads, so build them once on a fresh clone.
pnpm --filter @workspace/db run build
pnpm --filter @workspace/api-zod run build
pnpm --filter @workspace/api-client-react run build
pnpm --filter @workspace/replit-auth-web run build

cp .env.example .env    # then fill it in — see below
```

Push the schema to your database (drizzle-kit reads the shell environment, not
`.env`):

```bash
DATABASE_URL=postgresql://... pnpm --filter @workspace/db run db:push
```

Then run the two servers in separate terminals:

```bash
pnpm --filter @workspace/api-server run dev   # API on $PORT (use 8080)
pnpm --filter @workspace/vibescan run dev     # front end on 18425
```

The front end proxies `/api` to `localhost:8080`, so keep `PORT=8080` in
`.env` — and set it *there* rather than exporting it in your shell, or the Vite
dev server will try to bind the same port. Health check: `/api/healthz`.

Optional: `pnpm exec playwright install chromium` enables headless rendering of
JavaScript-heavy SPAs. Without it, scans fall back to raw fetch and log a
warning.

### Configuration

`.env` at the repo root is loaded by the API server via Node's
`--env-file-if-exists`. Real environment variables take precedence, so the file
is simply ignored in environments that inject their own. It is gitignored;
don't commit it.

| Variable | Required | Purpose |
|---|---|---|
| `PORT` | **yes** | API server refuses to boot without it. Use `8080` locally. |
| `DATABASE_URL` | **yes** | PostgreSQL connection string. |
| `DEEPSEEK_API_KEY` | no | Fallback AI analysis for Deep scans when a user hasn't set their own key. |
| `ENCRYPTION_KEY` | no | 32-byte base64 AES-256 key for user-supplied secrets. Without it, Settings → DeepSeek key returns 503. |
| `RESEND_API_KEY` | no | Email notifications (report ready, CVE alerts). |
| `APP_ORIGIN` | no | Base URL for links in emails. No trailing slash. |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` | no | Dormant — scans are free. |

Generate an encryption key with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## Development

```bash
pnpm run typecheck                              # whole workspace
pnpm run build                                  # typecheck + build every package
pnpm --filter @workspace/api-server run test    # 200 tests, 8 files
```

After editing `lib/api-spec/openapi.yaml`, regenerate and rebuild the
downstream packages — typecheck reads their emitted `.d.ts`, not their source:

```bash
pnpm --filter @workspace/api-spec run codegen
pnpm --filter @workspace/api-zod run build
pnpm --filter @workspace/api-client-react run build
```

[`replit.md`](replit.md) is the working engineering doc: the false-positive
rules new probes must follow, plus the accumulated gotchas — why some helpers
are deliberately duplicated between `scanner.ts` and `crawler.ts`, why Vitest
`fetch` mocks need `vi.stubGlobal`, and other things worth knowing before your
first change.

Key entry points:

| | |
|---|---|
| Scan engine | `artifacts/api-server/src/lib/scanner.ts` |
| API routes | `artifacts/api-server/src/routes/index.ts` |
| AI analysis | `artifacts/api-server/src/lib/deepseek.ts` |
| Catch-all/SPA suppression | `artifacts/api-server/src/lib/spaCatchAll.ts` |
| DB schema | `lib/db/src/schema/` |

## Deployment

The production target builds the front end and API together and serves the
static bundle from the API process — set `FRONTEND_STATIC_DIR` to the built
front end (`artifacts/vibescan/dist/public`) and run
`node artifacts/api-server/dist/index.mjs`. `.replit` holds the reference
configuration. Never set `NODE_TLS_REJECT_UNAUTHORIZED=0` in production.
