### Payloads, detection patterns, and safe templates
**Design principles:** parameterize, sandbox, and minimize side effects. Store payloads as templates with metadata: `id`, `type`, `impact`, `safe_by_default` (bool), `requires_consent` (bool).

#### XSS (refinement)
- **Detection approach:** compare reflected output across multiple encodings; use DOM rendering in headless browser to confirm script execution *only in sandboxed environment*.  
- **Safe PoC template (non‑destructive):** a benign marker that’s easy to detect server‑side or in DOM (avoid persistent JS execution).  
  - Example template: `{{param}} = "<img src=x onerror=console.log('vibescan-xss-{{id}}')>"`  
  - **Evidence:** DOM node present + console marker captured by headless browser.  
- **Avoid** payloads that exfiltrate data or trigger external callbacks unless running in an isolated lab.

#### SQLi
- **Detection approach:** use **time‑based** and **error‑based** checks with low impact; prefer boolean‑based probes that don’t alter data.  
- **Safe PoC template:** parameterized boolean test that causes a predictable response difference (e.g., `OR 1=1` vs `OR 1=2`) but never `DROP` or write operations.  
- **Evidence:** consistent response divergence across multiple encodings and parameter positions.

#### SSRF / Open Redirect / Host header
- **Detection approach:** use **internal-only** canary endpoints you control (or ephemeral canaries) to detect outbound requests; do not use third‑party callback services without consent.  
- **Safe PoC:** use a Vibecoders‑owned ephemeral domain/canary token to detect outbound fetches. Log and remove tokens after test.

#### Command injection / RCE (high risk)
- **Detection approach:** prefer **non‑destructive** indicators (e.g., environment echo, predictable error messages) and **never** run payloads that execute arbitrary commands in production.  
- **PoC policy:** require explicit opt‑in and a staging target; otherwise only flag probable indicators and recommend manual verification.

#### API / GraphQL / JSON endpoints
- **Detection approach:** fuzz JSON fields, test for schema mismatches, injection in JSON values, and parameter pollution. Use content‑type aware payloads and check for reflected JSON or error messages.  
- **GraphQL:** detect introspection enabled, overly permissive queries, and injection in query variables.

#### Static checks and configuration
- **TLS / HSTS / CSP / Security headers:** verify header presence, correct values, and HSTS preload eligibility. Test with multiple resolvers and user‑agent variations to avoid false positives.  
- **Dependency/CVE mapping:** map detected packages to OSV/CVE and include exploitability metadata; refresh feed daily.

### Safety, testing, and validation rules
- **Default safe mode:** GET‑only crawling, rate limits, no form submissions, no destructive verbs.  
- **Consent gating:** require explicit written consent for authenticated scans, aggressive payloads, or production POST/PUT/DELETE actions.  
- **Sandboxing:** run active exploit‑like checks in isolated environments (headless browsers, containerized scanners) and use ephemeral canaries for outbound detection.  
- **Rate limiting & politeness:** per‑host concurrency caps, exponential backoff on errors, and configurable crawl depth.  
- **Audit trail:** log every request/response, scanner config, and operator identity for each run.  
- **Safety checklist before run:** target allowlist, scope file, credentials verification, and emergency stop toggle.

---

### Validation, metrics, and continuous tuning
- **Key metrics to track:** **false positive rate**, **true positive rate**, **time to verify**, **pages scanned per minute**, **memory/CPU per scan**, **reproducibility rate** (PoCs that reproduce on first manual verification).  
- **Golden dataset:** maintain a labeled corpus (vulnerable vs clean) and run weekly evaluation to measure precision/recall.  
- **Feedback loop:** add a lightweight triage UI where users mark findings as valid/invalid; feed that back into ML heuristics or rule tuning.  
- **Canary experiments:** A/B test detection thresholds and payload encodings on non‑production targets to find the sweet spot between recall and noise.
